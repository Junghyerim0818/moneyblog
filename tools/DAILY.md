# 매일 아침 자동 글 규칙 (에코그라피)

## 만들 글
| 코너 | 언제 | 폴더 | labels | slug 예 |
|---|---|---|---|---|
| 증권 시황 | 매일 1개 | `posts/YYYY-MM-DD-market` | `["증권","시황", ...]` | `market-2026-11-17` |
| 뉴스 속 경제 용어 | 매일 1개 | `posts/YYYY-MM-DD-econ-영문용어` | `["경제","경제용어", 용어]` | `econ-term-stagflation` |
| 이번 주 공모주 | 매주 월요일 1개 (청약·상장 일정이 있을 때) | `posts/YYYY-MM-DD-ipo-week` | `["증권","공모주","공모주일정"]` | `ipo-week-2026-11-23` |
| 절세 | 이슈 있을 때만 | `posts/YYYY-MM-DD-tax-영문주제` | `["절세", ...]` | `tax-2027-year-end-change` |

- `meta.json`: `{"title", "labels", "mode": "publish", "slug"}`. slug는 영어 소문자·하이픈만 사용해요. 블로그 주소가 돼요.
- 글은 `tools/daily/YYYY-MM-DD.py`에서 `postkit.make()`로 만들어요. `tools/build_*.py` 형식을 그대로 따라요.

## 증권 시황 (전날 기준)
- 화~토 아침: 전 거래일 국내 마감(코스피·코스닥 지수와 등락률, 원·달러 환율 종가, 가능하면 외국인·기관 수급)과 간밤 미국 마감(S&P500·나스닥·다우)을 다뤄요. 시장을 움직인 이슈 2~3개와 오늘 볼 일정도 넣어요.
- 일요일: 한 주 정리(주간 등락, 이번 주 핵심 이슈 3개).
- 월요일: 이번 주 일정 미리보기(경제지표 발표·실적·정책 일정) + 주말 이슈.
- 전날이 휴장이면 그 사실을 적고, 직전 거래일 기준으로 써요.
- 그래픽: 지수 등락률 막대(signed), 핵심 숫자 kpi, 일정 checklist 등. **개별 종목 주가 차트는 넣지 않아요**(공모주 상장일 글의 공모가 대비 등락률 막대만 예외).
- **추세 차트(필수, 1~2개)**: 지수·환율 흐름 그래프를 넣어요. 트레이딩뷰 같은 외부 위젯은 쓰지 않아요(사용자 결정).
  - 데이터는 '시세 데이터' 워크플로(`.github/workflows/market-data.yml`)가 매일 06:10·평일 18:10 KST에 받아서 `tools/data/market/*.csv`로 커밋해요. `git pull` 후 `_updated.txt`로 갱신 시각을 확인해요. 오래됐으면 GitHub MCP `actions_run_trigger`(run_workflow, `market-data.yml`, ref main)로 한 번 돌리고 끝나면 다시 pull 해요.
  - 원고에서는 `postkit.trend_graphic(file, 이름, days, end=글 기준일, check=검증한 종가)`를 graphics 목록에 넣어요. 이름: KOSPI, KOSDAQ, USDKRW, SP500, NASDAQ, DOW, DXY, US10Y, WTI.
  - `check`에는 웹 검색으로 2곳에서 확인한 종가를 넣어요. 차트 마지막 값과 0.5% 넘게 다르면 멈추니, 그때는 날짜·데이터를 확인하고 차트를 빼요.
  - 기본 조합: 화~토는 코스피 60거래일 + 원·달러 환율 60거래일(필요하면 S&P500·나스닥). 일요일 주간 정리는 20거래일, 월요일은 60거래일.
  - 환율 데이터는 24시간 국제 시세라 서울 외환시장 종가와 조금 달라요. 본문 숫자는 서울 종가를 쓰고, 차트 출처 문구는 그대로 둬요.

## 이번 주 공모주 (증권 > 공모주 탭, 매주 월요일)
- 블로그 테마의 증권 하위 탭(전체·시황·공모주·속보·금융 기초)은 라벨로 나뉘어요. 공모주 글은 첫 라벨 "증권", 둘째 라벨 "공모주"로 둬요.
- 월요일 아침에 그 주(월~금) 일반 청약·상장·기관 수요예측 일정을 정리해요. 청약도 상장도 없는 주면 쓰지 않아요.
- 종목명·청약일·(희망/확정) 공모가·주관사·상장일·경쟁률은 출처 2곳에서 확인해요. 확정 전 공모가는 '희망 범위'라고 적어요.
- 그래픽: 일정 checklist, 청약 종목 table, 상장 종목 table(공모가·경쟁률), 증거금·경쟁률 bars 등. 상장 후 주가 차트는 넣지 않아요.
- "청약하세요/하지 마세요" 같은 권유는 하지 않아요. 확인할 숫자(기관 경쟁률·의무보유확약·유통 물량)만 안내해요.
- 처음 보는 사람을 위해 기초 글(https://ecograpy.blogspot.com/2026/11/ipo-subscription-basics.html) 링크를 걸어요. meta에 `"coupang": false`.
- ledger.json의 `ipo_posts`에 기록해요.
- **청약 체크 글 (화~금 아침, 그날 일반 청약이 시작되는 종목이 있을 때)**: 사용자가 "공모주 일정에 맞춰 계속 올려 달라"고 했어요. 매일 아침 그날 청약을 시작하는 종목을 확인하고, 있으면 한 글로 묶어 써요.
  - 폴더 `posts/YYYY-MM-DD-ipo-subscription`, labels `["증권","공모주","청약"]`, slug `ipo-subscription-YYYY-MM-DD`, `"coupang": false`.
  - 넣을 것: 확정 공모가(희망 범위 중 위치), 기관 수요예측 경쟁률, 의무보유확약 비율, 상장일 유통 가능 물량, 청약일·환불일·상장 예정일, 주관·인수 증권사, 균등배정 최소 증거금(최소 청약 수량 × 공모가 × 50%) 계산, 회사가 하는 일 한두 줄.
  - 확정 공모가·경쟁률은 출처 2곳에서 확인해요. 확정 공모가가 아직 안 나왔으면 쓰지 않아요.
  - 그래픽 4개 정도: 썸네일, 핵심 숫자 kpi, 일정 checklist, 종목 비교 table. 권유 문장은 쓰지 않아요.
  - 스팩(SPAC)만 있는 날은 쓰지 않아요. 같은 종목으로 이미 쓴 청약 체크 글이 ledger `ipo_posts`에 있으면 다시 쓰지 않아요.
  - 월요일에 청약을 시작하는 종목은 '이번 주 공모주' 글 안에 청약 체크 내용을 함께 넣어요.
- **상장일 글 (평일 저녁 작업, 그날 신규 상장한 공모주가 있을 때)**: 사용자가 "상장일에 시초가와 흐름을 써 달라"고 했어요. 장 마감 뒤 저녁 작업(18:4x KST)에서 그날 상장한 종목(스팩 제외)을 한 글로 묶어 써요.
  - 폴더 `posts/YYYY-MM-DD-ipo-listing`, labels `["증권","공모주","상장"]`, slug `ipo-listing-YYYY-MM-DD`, `"coupang": false`.
  - 넣을 것: 공모가, 시초가(공모가 대비 %), 장중 고가·저가, 종가(공모가 대비 %), 거래대금(가능하면), 장중 흐름 설명(시초가 뒤 올랐는지 밀렸는지, 언제 고점·저점이었는지), 청약 때 숫자(경쟁률·확약) 다시 보기, 다음에 볼 것(의무보유 해제 일정 등).
  - 시초가·종가는 출처 2곳(기사·거래소/포털 시세)에서 확인해요. 확인이 안 되는 값은 빼고, 시초가·종가 둘 다 확인이 안 되면 그 종목은 빼요.
  - 그래픽: 썸네일, 공모가 대비 시초가·고가·저가·종가 등락률 bars(signed), 핵심 숫자 kpi, 청약→상장 숫자 table. 이 상장일 글에서는 공모가 대비 등락률 막대만 예외로 허용하고, 주가 시계열 차트는 넣지 않아요.
  - "지금 사세요/파세요" 같은 권유는 쓰지 않아요. 이미 쓴 종목은 ledger `ipo_posts`(type "상장")로 확인해 다시 쓰지 않아요.
  - 다음 날 아침 시황 글에서 이 글 링크를 걸어요.

## 속보 글 (평일 저녁 점검, 큰 이슈가 있을 때만)
- '평일 저녁 속보 점검' 예약 작업이 평일 18:4x KST에 돌아요. 그날 시장에 큰 영향을 준 갑작스러운 이슈가 있을 때만 1개 써요.
- 기준(하나 이상): 코스피·코스닥 ±3% 이상 또는 사이드카·서킷브레이커, 원·달러 환율 하루 15원 이상 변동, 기준금리 깜짝 결정·정부 긴급 대책, 시장 전체를 흔든 대형 기업·지정학 사건.
- 기준에 못 미치면 아무것도 올리지 않아요(커밋도 하지 않아요). 다음 날 아침 시황에서 다뤄요.
- 폴더 `posts/YYYY-MM-DD-breaking-영문주제`, labels `["증권","속보", ...]`, slug `breaking-YYYY-MM-DD-영문주제`. 구성: 3줄 요약 → 무슨 일이 있었나 → 숫자(출처 2곳) → 왜 중요한가 → 내 돈과의 연결 → 앞으로 볼 것 → FAQ → 출처 → NOTE. 그래픽 3~4개(추세 차트 포함 가능).
- ledger.json의 `breaking_posts`에 기록하고, 다음 날 아침 시황에서 "어제 저녁 속보" 링크를 걸어요.

## 뉴스 속 경제 용어
- 최근 뉴스에 실제로 나온 용어 하나를 골라요. `ledger.json`의 `econ_terms_deep`에 있는 용어는 다시 쓰지 않아요.
- `econ_terms_basics`에 있는 용어는 이미 기초 글에서 한 줄로 다뤘어요. 새 용어를 먼저 쓰고, 기초 용어는 '깊게 보기'로만 써요.
- 구성: "이 뉴스에 나온 그 단어" → 한 줄 뜻 → 원리 그래픽 → 내 돈과의 연결 → 비슷한 용어 비교 → FAQ.

## 절세 (이슈 있을 때만)
- 세법 개정 확정·정부 발표, 신고·납부 기한 임박(5월 종합소득세·양도세, 1~2월 연말정산), 새 제도 시행 같은 이슈가 있을 때만 써요.
- 새 이슈가 없으면 쓰지 않아요. `tax_posts`와 겹치는 주제는 건너뛰어요.

## 공통 원칙
- 한국어, 해요체, 토스처럼 쉬운 문장으로 써요. 본문은 1,500~2,500자예요. 구성은 3줄 요약(mg-lead) → 목차 → 본문 → 그래픽 4~5개 → FAQ → 출처 → NOTE 순서예요.
- **숫자는 모두 웹 검색으로 확인해요.** 지수 종가·환율 같은 핵심 숫자는 출처 2곳에서 일치해야 써요. 확인이 안 된 숫자는 빼요.
- 시황 글에서 지수 숫자를 확인하지 못하면 그날 시황 글은 `mode: "draft"`로 올리고, 실행 결과에 이유를 남겨요.
- 기사 문장을 베끼지 않아요. 출처는 링크로 남겨요. 매수·매도 권유는 하지 않아요.
- 그래픽을 만든 뒤 이미지를 직접 열어 글자가 잘리거나 겹치지 않는지 확인해요. 표 칸의 글자는 짧게 써요.
- 다 쓰면 `ledger.json`을 갱신하고, `python blogger/publish.py --dry-run`으로 확인한 뒤 커밋·push 해요. 그러면 GitHub Actions가 블로거에 공개해요.
- push 뒤 `gh run list`로 워크플로가 성공했는지 확인해요. 실패하면 로그를 읽고 원인을 보고해요.

## 쿠팡 파트너스 (tools/coupang.json, 지금은 enabled: false)
- 켜져 있으면 게시할 때 자동으로 글 끝(FAQ 위)에 책 1~2개 카드가 들어가고, 썸네일 아래에 대가성 문구가 붙어요.
- 글 주제에 딱 맞는 키워드가 있으면 meta.json에 `"coupang": {"keyword": "환율 투자 책"}`처럼 지정해요. 시황 글은 `"coupang": false`로 둬요.
- 금융상품·투자 서비스·코인 관련 상품은 넣지 않아요.

## 조회수 보고 (매일 아침 결과 메시지에 함께)
- '블로그 조회수' 워크플로(`.github/workflows/stats.yml`)가 매일 05:55 KST에 블로거 API 조회수를 받아 `tools/data/stats/pageviews.csv`(하루 한 줄)와 `latest.json`에 기록해요.
- 아침 작업은 `git pull` 후 `latest.json`의 date가 오늘이 아니면 GitHub MCP `actions_run_trigger`로 `stats.yml`을 돌리고 끝난 뒤 다시 pull 해요.
- 결과 메시지에 한 줄로 넣어요: "조회수: 지난 24시간 N회(day) · 최근 7일 N회(d7) · 30일 N회(d30) · 누적 N회(all)". day가 비어 있으면(첫 기록) 생략해요. 전날보다 크게 늘었으면(2배 이상) 한마디 덧붙여요.
- 블로거 API는 글별 조회수를 주지 않아요. 글별 순위는 블로거 관리 화면 '통계'에서 봐야 해요.
